# EventBus — the generic event hub

EventBus is a **generic, app-agnostic** hub. Every event in the data plane flows
through it: producers publish; stratum/timedb/graphdb subscribe. EventBus's
hand-written code names **no vservice** — every topic, publish RPC, and dispatch is
generated from the tacplus contract.

> Authoritative annotation contract: `schematic/tacplus/docs/RECORD_EVENT_MODEL.md`.

## Role

```
external:  client  → gateway ─[event]→ EVENTBUS ─┬─→ stratum   (record)
internal:  service          ─[event]→ EVENTBUS ─┤   timedb    (timeseries projections)
                                                 └─→ graphdb   (graph projections)
```

Both producer paths land here identically; EventBus fans each event to its
subscribers. It cares only about the type, not the producer.

## Topics + publish RPCs (generated from `event`/`record`)

- Any message annotated `event` (or `record`, which **is** an event) gets an EventBus
  **topic** and a **publish RPC**, generated by tacplus.
- The producer surface is **declared on the annotation, not defaulted**: `c2s` exposes
  the publish RPC to external clients (via gateway), `s2s` to internal services (e.g.
  the `*-proxy` services). An internal-only event is S2S and is **not** exposed C2S.
- `record`s are additionally fanned to the stores (stratum stores the full record;
  timedb/graphdb extract their projections). Event-only messages (e.g. trace events)
  flow through but are not stored.

## Subscriptions

Subscribers are derived, not hand-wired: a `record_store`/`graph_store`/
`timeseries_store` service auto-subscribes to the topics carrying the events (and
projection source types) it must ingest. EventBus dispatches generically; per-type
handling lives in the generated code of each subscriber.

## What is generated vs hand-written

- **Generated:** topics, publish RPCs (with the declared C2S/S2S surfaces), trace
  dispatch, and per-type routing — all from `event`/`record` annotations.
- **Hand-written (vservice-neutral):** the generic hub/dispatch. No event type is
  special-cased; adding/removing a vservice only regenerates + rebuilds EventBus.
